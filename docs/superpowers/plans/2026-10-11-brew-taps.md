# Trusted Homebrew taps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Formulas from third-party Homebrew taps are recorded in chezmoi data and installed only from taps the machine's owner trusted once at `chezmoi init`; the bogus `vector` cargo entry is gone.

**Architecture:** Tap formulas live in one list, `brew_tap_packages`, as full `owner/tap/formula` names (the tap is the first two segments). `.chezmoi.toml.tmpl` reads that list from the JSON and asks `promptBoolOnce` once per tap, storing answers in the local config under `[data.brew_tap_trust]`. Script 02 adds a formula to `brew install` only when its tap's answer is `true` and prints a skip line otherwise. The schema keeps tap formulas out of the other brew lists, because `brew install owner/tap/formula` taps on its own and would bypass the prompt.

**Tech Stack:** chezmoi v2.69 (`promptBoolOnce`, `include`, `fromJson`, `toToml`), jq 1.7 schema module, fish 4.8 + fishtape, mise file tasks, Homebrew 4.

**Spec:** the Background section below (decisions agreed in session 2026-10-11; original sketch in the "brew taps + vector" memory note).

## Background (signals measured before planning, 2026-10-11)

- `vectordotdev/brew` (up to date at 0.59.0) has macOS-only URLs; on Linux `brew install --dry-run vectordotdev/brew/vector` says "is a HEAD-only formula" (a full Rust source build). homebrew-core has no `vector` (formulae.brew.sh API 404).
- crates.io `vector` is an unrelated library (`stainless-steel/vector` 0.4.1, a nearest-neighbour database). The `cargo_binaries` entry never installed vectordotdev's vector; binstall failing was all that kept the wrong crate off the machine.
- **Decision:** drop `vector` from data entirely (it stays a manual per-machine install; `~/.vector/bin` remains in this machine's `fish_paths_local`). Record only the `oven-sh/bun` tap (formula `oven-sh/bun/bun`, installed here already).
- `.chezmoidata/` is **not** loaded when the config template runs (`get . "brew_packages"` is absent under `--init`); `include ".chezmoidata/packages.json" | fromJson` works, also against a temp `--source` dir.
- `promptBoolOnce . (list "brew_tap_trust" "owner/tap") "…"`: a list path handles the `/` in tap names, and a stored answer is reused without prompting.
- A real `chezmoi init` with no TTY and **no stored answer fails**: `could not open a new TTY`. With a stored answer it succeeds without a TTY. So `chezmoi.test.toml` (seeded into the Docker build) must answer every tap.
- `chezmoi execute-template --init` never prompts: an unanswered `promptBoolOnce` renders `false`.
- `toToml` of a dict quotes slash keys (`"oven-sh/bun" = true`) and renders an empty dict as an empty string; `get (dict) "x"` is falsy; `regexReplaceAll "/[^/]*$" "oven-sh/bun/bun" ""` gives `oven-sh/bun`.
- `brew list --versions oven-sh/bun/bun` exits 0 for an installed tap formula, so `pkg remove`'s installed check works with full names.

## Global Constraints

- No inline scripting (`python -c`, ad hoc `bash -c` programs); use tests, `scripts/`, jq, chezmoi.
- Use `trash`, never `rm`.
- `make test-unit` is read-only against the live home and source: tests use temp copies, temp configs, `--source` temp dirs and stubs.
- JSON data changes go through `scripts/data-edit` or the mise tasks; the one exception is adding the new empty key in Task 2 (data-edit has no add-key operation), done by an edit reviewed in the commit.
- No absolute home paths (`/home/<user>`) in committed files; the pre-push audit for personal data applies.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A tap formula put in `brew_packages*` would be tapped and installed by `brew install` with no prompt → the schema rejects any `/` there (Task 2 tests; Task 5 `pkg add brew owner/tap/formula` test).
- A tap added to data without an answer in `chezmoi.test.toml` makes the Docker `chezmoi init` fail with "could not open a new TTY" → Task 3 test that the test config answers every tap in data.
- A stored answer is reused by re-init without prompting (a "no" stays no, a "yes" stays yes) → Task 3 "stored answer is kept" test.
- Several formulas from one tap give one prompt and one key, and script 02 decides per tap, not per formula or globally → Task 3 "one key per tap" test, Task 4 "trust is per tap" test.
- A machine with no tap formulas, or with a tap removed from data, still renders a valid config without the stale entry → Task 3 "no taps" and "dropped tap" tests (both parsed back through `chezmoi --config`).

```jq
# A tap formula runs code from a third-party repository, so it lives only in
# brew_tap_packages as owner/tap/formula, where chezmoi init asks to trust its tap.
# `brew install owner/tap/formula` taps on its own, so a slash in another brew list
# would bypass that prompt.
def tap_violations:
  [ (.brew_tap_packages | arrays | .[] | strings
      | select(test("^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+/[A-Za-z0-9@._+-]+$") | not)

      | .[$k] | arrays | .[] | strings | select(contains("/"))
      | "\($k): \(tojson) names a tap formula; use brew_tap_packages") ];
```
